# 国自然技术路线图（A4 竖版 · 评审视角）

**读者不是同行，是评审**。他们看这张图只回答三个问题：**要解决什么问题 → 分几步做 → 做完能得到什么**。
所以国自然图的成功标准不是"好看"，而是**逻辑闭环一眼可见、模块都有产出、创新点藏不住**。

和 `tech-route-atlas`（期刊路线图/图形摘要，横向、图元密集）的分工：

| | 期刊路线图 | 国自然技术路线图 |
|---|---|---|
| 读者任务 | 这张图发现了什么 | 这个项目**该不该资助** |
| 画布 | 254×142.9 横版 / 300×189.5 | **A4 竖版 210×297**（横版只在正文已横排时用） |
| 中文 | KaiTi | **SimHei（黑体）**，不用宋体/楷体 |
| 图元 | 30–60 个插画 | **0–6 个**，文字卡为主；图标只在 ≥12 mm 独立位放 illustration |
| 允许 | 只画已得机制 | 可画**未完成**计划与风险预案 |
| 底线 | 字号 ≥5.5 pt | **实印 ≥8 pt**，放不下就砍模块，不许缩字 |

## 五条铁律

1. **一页一图，绝不跨页**。A4 能装的是 3–5 个模块；装不下就砍模块或拆成"总图 + 分图"，不要压缩字号。
2. **模块必须有可验证产出**。每个研究内容右边都配"▸ 可验证产出"，写具体的曲线/通路/指标集/论文，不写"深入研究"。
3. **创新点必须有颜色**。全图唯一高饱和色只给创新点（示范用 `#b87333`），其他一律低饱和。
4. **先过灰度**。打印成黑白仍能分出层级才算合格：一级深、二级中、三级浅，靠**深浅**不只靠色相。
5. **字数是硬约束**。模块标题 ≤18 字，目标 1 行 ≤30 字，关键技术/产出一行 ≤18 字，创新点一条 ≤18 字。超了就砍字，不要换行硬塞。

## 画布与字号

```python
from routekit import CANVAS
W, H = CANVAS.nsfc_a4            # 210 × 297 mm（新增预设）
# CANVAS.nsfc_a4_landscape = (297, 210) / CANVAS.nsfc_a4_half = (210, 148)
cv = Canvas(W, H, palette="cell", cjk_font="SimHei")
```

| 层级 | 字号 | 用途 |
|---|---|---|
| 大标题 | 18 pt bold | 项目题目（放得下就 20，两行就 16） |
| 副标题 | 9.6 pt | 项目类型 + 年份 + "技术路线图" |
| 分区标题 | 10 pt bold | 科学问题 / 研究内容 / 创新点 / 预期成果 / 风险 |
| 模块标题 | 13 pt bold | 研究内容一、二、三 |
| 小标题 | 9 pt bold | 关键技术、可验证产出、论文、知识产权… |
| 正文 | 9.2 pt | 目标行、卡片条目 |
| 最小 | 8.2 pt | 风险/对策、脚注；**不得低于 8 pt** |

字号取 0.2 的倍数，SimHei 的 bold 是伪粗（实测墨量 +26.6%，够用，不必换字体）。

## 先写规格，再写代码

```
画布: nsfc_a4 210×297，边距 12 mm，单页
故事: 一句话（谁 → 干预什么轴 → 改善什么表型 → 落在什么成果）
分区: A 科学问题与假说 / B 研究内容一~三 / C 创新点 / D 预期成果 / E 风险与对策
箭头: 拓扑表（见下），左侧竖向主干 + 区内横向
配色: 2 主色深浅三级 + 1 强调色（只给创新点）
```

| ID | From | To | 线型 | 语义 | 优先级 |
|----|------|----|------|------|--------|
| B0 | 工作假说 | 研究内容一 | 实线 | 假说落地 | P0 |
| B1 | 研究内容一 | 研究内容二 | 实线 | 表型发现→机制解析 | P0 |
| B2 | 研究内容二 | 研究内容三 | 实线 | 机制→干预验证 | P0 |
| H1 | 前期基础 | 科学问题 | 实线 | 发现→提炼问题 | P0 |
| H2 | 科学问题 | 工作假说 | 实线 | 问题→提出假说 | P0 |

主干箭头要**落在编号圆点（chip）上**，不要落进标题首字；跨区不连斜线，不画往返交叉。

## 六步工作流

1. **定构型**：按项目类型从 `references/archetypes.md` 选一种（面上/青年默认"三段式"）。
2. **写规格**：上面 4 行 + 箭头拓扑表，先给用户看，别直接开画。
3. **搭骨架**：只放 5 个分区外框 + 分区标题 + 三个模块卡的编号圆点和空标题，导出看比例。
4. **填文字**：按"目标 → 关键技术 → 可验证产出"三要素填；每填一行用 `routekit.measure.text_w_mm()` 量一下宽度。
5. **连箭头**：主干 3 条（lw 1.4）+ 区内 2 条（lw 1.1）；辅助/备选才用虚线。
6. **自检 + 交付**：`static_report(cv, mode="print")` 0 error → 渲染 PNG 目视 → **转灰度再看一遍** → `export.render(dpi=600, also_pdf=True)`。

`mode="print"`（不是 `deck`）才会按 5.0 pt 印刷地板判，而国自然要自己把地板提到 **8.0 pt**：看到 `small-text` 警告一律当成 error 处理。

## 模块卡的三要素

每张卡固定三行结构，少一行就会被打"内容=实验步骤"：

```
[编号] 研究内容一  <18 字的科学命题，不是动作>
研究目标：<30 字以内，回答"要搞清什么规律/机制/效应">
关键技术：● 具体手段（带方法名与关键参数）  可验证产出：▸ 具体交付物
          ● ……                                      ▸ ……
          ● ……（≤3 条，多了就并）
```

- "关键技术"写**手段**：GC-MS、条件敲除鼠、类器官 + TEER、单细胞。
- "可验证产出"写**能被考核的东西**：增龄变化曲线、分子通路、干预方案、指标集、论文数。
- 不要写"深入研究其机制"这种不可验证的动词。

## 配色与灰度

- 主色取一类色相的深/中/浅三级（示范 `#1b3a63 / #2e6e9e / #5a8fbf`）承载三个模块的层级；强调色只给创新点。
- 底纹一律 `#f6f9fb` / `#ffffff`，细边框 `#c2cfda` lw 0.5；禁渐变、禁阴影、禁 3D、禁圆角大于 2 mm。
- 交付前把 PNG 转灰度存一份自看：`Image.open(png).convert("L")`。深浅分不开就改明度，不要靠换色相。

## 常见错误（评审扣分点）

| 现象 | 为什么错 | 修法 |
|---|---|---|
| 画成甘特图 / 时间轴 | 面上/青年正文不需要时间轴式 | 换成三段式或顺序式；年度安排写正文 |
| 内容=实验步骤清单 | 评审看不到科学问题 | 每卡先写"研究目标"，再写手段 |
| 模块没有产出 | 无法判断能否结题 | 每卡右侧固定"可验证产出"栏 |
| 科学问题埋在角落 | 评审 10 秒找不到核心 | 放第一区且最大，红/深色标题 |
| 创新点没有颜色 | 一眼扫不到 | 全图唯一高饱和底色条 |
| 箭头来回交叉 | 逻辑断裂感 | 主干单向；分支只在区内 |
| 字号 < 8 pt 塞满 | A4 实印看不清 | 砍模块、砍字数，不砍字号 |
| 跨页 | 打印后逻辑断开 | 单页；超了拆图 |
| 与正文对不上 | 评审对照正文发现不一致 | 图里每个数字都来自正文 |
| 配色 5 种以上 / 有渐变 | 显廉价 | 2 主色 + 1 强调色，纯色平涂 |

## 交付

- 三件套：`nsfc-route.pptx`（原生形状，可在 PowerPoint 里改字改色）+ `nsfc-route.png`（600 dpi，插 Word 用）+ `nsfc-route.pdf`（矢量，送审/打印用）。
- 插图尺寸：A4 正文里图占满一行时，实际宽度 ≈ 160 mm；**按 160 mm 打出来仍要 ≥8 pt**。
- 一张图配 3–5 行图注，写清"模块 → 产出"的对应关系，方便评审对照正文。
